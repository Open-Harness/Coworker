# doings

The one registry of what can be done on the console. Pure.

Not built. `types.ts` is the contract and compiles; `service.ts` says so where it is called. What it must do: spec U3, C6, C7, C10 in
[docs/spec.md](../../../docs/spec.md). What shows it: the evals under `doings` in [docs/book.md](../../../docs/book.md).

## Settled by the evals

- A person's own setting can only make a doing less; their role is the floor, and the co-worker's own `role` holds for it too.
- The co-worker alone has what was set for it, else the registry's; never more than ask where the doing stops, and never anything for a doing whose id begins `ask.`. On someone's behalf it has the less of that and what the person may.
- A doing is found by the words of its label or its id, in any case, spaces at the ends dropped, the words as plain text and not as a pattern. Results come in the order ask (once), go, do, find, and within a group the same, begins with, has it, then only the `about`.
- A sentence has the name it is given and each `{field}` filled once, values never filled in again; a secret is never a slot.
- A walk is one `go`, one `fill` for each field that has a value in the doing's own order, and one `press` last; only the last may be the person's, and is when the doing stops.
- `manager.make.above` makes the manager under that one (R1, refused like `manager.move` when wider); `manager.settings` has `connection` beside `model` (the model's own connection, else the first that lists it).
